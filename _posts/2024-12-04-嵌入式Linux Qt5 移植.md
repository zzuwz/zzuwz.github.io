## 问题背景
buildroot-2018.11是最后一个支持Qt4.8.7的版本。前期使用Qt4.8.7,因此文件系统的构建一直基于buildroot-2018.11。后续要选择Qt5 的最新版本 Qt5.15.14 ，buildroot 的最新版本支持Qt5.15.14,但是在编译webengine 模块的时候报错。同时如果选择最新版本的buildroot,相当于系统进行了整体的升级，尤其是glibc变化很大。

> **期望目标** :使用原来的文件系统，同时支持Qt5。


## 研究过程

进行了一系列的尝试，包括：
1. 使用buildroot 2024.8 编译 Qt5.15.14  **失败**
2. 使用buildroot 2021.2 长期支持版本编译 Qt5.15.2 **成功**
3. 使用ubuntu 20.04 编译Qt 5.15.14 **成功**
4. 使用ubuntu 18.04 编译Qt 5.15.14 **成功**
5. 根据ubuntu 18.04 编译的Qt5 产物，移植到原来的文件系统中，实现期望目标。


ubuntu 18.04 和buildroot 2018.11 都是用的GLIBC 2.28，因此文件系统几乎可以认为是一致的。


ubuntu 18.04 编译Qt5.15.14
```shell
#安装依赖
sudo apt-get install libfontconfig1-dev libxss-dev  libwebp-dev libjsoncpp-dev libopus-dev libminizip-dev libavutil-dev libavformat-dev libavcodec-dev libevent-dev libvpx-dev libsnappy-dev libre2-dev libprotobuf-dev protobuf-compiler libxcursor-dev libxcomposite-dev libxdamage-dev libxrandr-dev libxtst-dev libxss-dev libdbus-1-dev libevent-dev libfontconfig1-dev libcap-dev libpulse-dev libudev-dev libpci-dev libnss3-dev libasound2-dev libegl1-mesa-dev gperf bison nodejs  libgles2-mesa-dev libgbm-dev libsrtp2-dev  libgles2-mesa-dev libgbm-dev libsrtp2-dev  libicu-dev libmtdev1  libinput10 libxkbcommon0  libfontconfig1-dev libxss-dev  libwebp-dev libjsoncpp-dev libopus-dev libminizip-dev libavutil-dev libavformat-dev libavcodec-dev libevent-dev libvpx-dev libsnappy-dev libre2-dev libprotobuf-dev protobuf-compiler

#尽可能减少依赖，配置如下
./configure -prefix /usr/local/Qt-5.15.14 -webengine-embedded-build -qpa eglfs  -eglfs -no-xcb -kms -gbm -linuxfb  -opengl es2 -no-xcb-xlib -no-libinput -no-xkbcommon -opensource -confirm-license  -tslib -no-mtdev -no-icu -no-glib
```


### 升级mesa3d

经过测试，ubuntu18.04 通过apt-get 安装的mesa3d 不支持嵌入式装置上的gpu,通过升级mesa3d 可以解决该问题，升级到20.3.5版本能用。
```shell
sudo apt install -y build-essential meson ninja-build pkg-config \ libpciaccess-dev xutils-dev libudev-dev libxcb1-dev \ libxcb-dri2-0-dev libxcb-dri3-dev libxcb-present-dev \ libxcb-sync-dev libxcb-glx0-dev libxcb-xfixes0-dev \ libxshmfence-dev libdrm-dev

mkdir build
meson build/ --prefix=/usr/local/mesa --default-library=shared --buildtype=release -Dgallium-omx=disabled -Dpower8=disabled -Dllvm=disabled -Dgallium-opencl=disabled -Dglx=disabled -Dgallium-xa=disabled  -Dshared-glapi=enabled -Dgallium-drivers=iris,swrast -Dgallium-extra-hud=true -Ddri3=disabled -Dshared-glapi=enabled -Dglx-direct=true -Ddri-drivers=i915 -Dvulkan-drivers= -Dosmesa=none -Dopengl=true -Dgallium-va=disabled -Dplatforms= -Dgbm=enabled -Degl=enabled -Dgles1=enabled -Dgles2=enabled -Dgallium-xvmc=disabled -Dlibunwind=disabled -Dgallium-vdpau=disabled -Dlmsensors=disabled -Dzstd=disabled 
ninja -C build/
sudo ninja -C build/ install
```

### Qt5运行测试
将ubuntu18.04 里面编译的Qt5 的库拷贝到嵌入式装置上，由于系统不一致，会存在缺少配置文件，缺少动态库的问题。在测试中常用的环境变量收集如下：
```shell
export QT_QPA_PLATFORM_PLUGIN_PATH=/Qt5/plugins/platforms
export QT_QPA_PLATFORM=linuxfb
export QT_QPA_FB_DRM=1
export LD_LIBRARY_PATH=/Qt5/lib


export QT_QPA_PLATFORM=eglfs
#打开Qt5 调试信息，可以看到缺少哪些动态库
export QT_DEBUG_PLUGINS=1

#设置mesa3d 驱动目录 默认是在/etc/dri目录下
export LIBGL_DRIVERS_PATH=/c/shrlib/dri

#有时候还是会启动失败，则可以通过strace看该程序运行的时候，打开哪些文件或者动态库失败，导致崩溃的
strace -e openat  ./textedit | grep "*.so*"
```
