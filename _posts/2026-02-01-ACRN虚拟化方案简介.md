ACRN 是Intel推出的基于x86平台的开源虚拟化方案。项目网站为：[https://projectacrn.org](https://projectacrn.org)   代码仓库为：[https://github.com/projectacrn/acrn-hypervisor](https://github.com/projectacrn/acrn-hypervisor)   文档说明链接为: [https://projectacrn.github.io/latest/index.html](https://projectacrn.github.io/latest/index.html) 
整体架构如下图所示：
![](/assets/image/Pasted%20image%2020260201170202.png)

从此图中可以看出，ACRN有三种类型虚拟机。分别为 **Pre-launched User VMs** , **Service VM** ,**Post-launched User VMs** 。
预启动虚拟机是针对强实时要求的使用场景，从图中也可以看出与Service VM 和Post-launched User Vms 是完全隔离的。Service VM 和后启动虚拟机则比较容易理解。Service VM等价与一个操作系统上面部署了vmware，而后启动虚拟机 则是vmware 的虚拟机镜像。跟普通的vmware的虚拟机镜像相比后启动虚拟机是可以透传设备实现硬件资源的使用，同时各个后启动虚拟机可以通过网络，共享内存等方式进行通信。


ACRN的帮助文档非常详细，可以指导我们逐步搭建起虚拟化环境。

构建实时系统的时候，CPU必须勾选Real-time vCPU,否则实时性无法保证。

## qemu-img 处理虚拟机镜像

虚拟磁盘的类型常见的有raw，qcow2 两种格式。可以借助qemu-img命令来管理。raw格式性能比qcow2好。acrn中使用的是raw格式。qcow2格式占空间较小。qemu-img 创建磁盘,默认是raw格式。

```shell
# qemu-img create t1.img 1g
Formatting 't1.img', fmt=raw size=1073741824
# qemu-img info t1.img     
image: t1.img
file format: raw
virtual size: 1 GiB (1073741824 bytes)
disk size: 4 KiB


指定qcow2格式
➜  kvm qemu-img create -f qcow2 t2.qcow2 512M
Formatting 't2.qcow2', fmt=qcow2 size=536870912 cluster_size=65536 lazy_refcounts=off refcount_bits=16
➜  kvm qemu-img info t2.qcow2                
image: t2.qcow2
file format: qcow2
virtual size: 512 MiB (536870912 bytes)
disk size: 196 KiB
cluster_size: 65536
Format specific information:
    compat: 1.1
    lazy refcounts: false
    refcount bits: 16
    corrupt: false
➜  kvm ls -hl t2.qcow2 
-rw-r--r-- 1 wz1026 wz1026 193K 2月   8 12:27 t2.qcow2


```

qemu-img 命令可以增加和减小raw格式，但是只能增大qcow2格式。
```shell
qemu-img resize t2.qcow2 1G
qemu-img info t2.qcow2   
#增量增添加1G  
qemu-img resize t2.qcow2 +1G
```

格式转换,-O后面跟的是要输出的格式
```shell
qemu-img convert -f qcow2 -O raw rt_vm.qcow2  rt_vm.img
qemu-img convert -O qcow2 -f raw ./rt_vm.img ./rt_vm.qcow2
```
